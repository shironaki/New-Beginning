# 🕹 3D-переход — план и текущее состояние

Документ отвечает на приказ «переконструктируй проект под 3D формат плавным
переходом, где надо — оставляй 2D-кодовый формат, где надо — добавь пиксели».
Ключевое слово — **плавным**: ни одна стадия не выключает предыдущую, пока
следующая не сравняется с ней по кадру. Правило для всех стадий: живой слой
обязан дать тот же силуэт, что и лист (иначе — откат на лист, а не чёрный
экран), и проверка этого есть в `npm test`.

## Стадии

| # | что | состояние | чем проверяется |
|---|---|---|---|
| 0 | Герой: живой THREE-рендер скиннутого меша поверх запечённого листа | **работает** (`js/render/hero3d-live.js`) | `npm run hero:live` (якорь кисти ≤ 1 px), `npm run hero:frame` (силуэт против листа) |
| 1 | Пропы: меши из glTF-паков, запечённые в кадровые спрайты | **работает** (`tools/prop-bake.js` → `js/render/propsprites.js`) | `npm run props:audit` (21 вид), `npm run play 80` |
| 2 | Земля: проективный рельеф + нарисованный тон (ступени, дизер, пятна материала) | **сделано в блоке 80.1** (`js/render/terrain.js`) | `npm run frame:check`, тест «земля в печёном рельефе нарисована» |
| 3 | Свет: общий контракт «солнце → пропы → живой герой» + откат на лист по диагнозу | **работает** (`propSunFor` / `setPropSun` / `liveSun`; `hero3d.js` падает на лист при `bad-mesh`, `empty-frame`, `context-lost`) | `npm run frame:check`, тест «отказ живого слоя = лист» |

### Стадия 4 — ближние пропы живьём

1. `js/render/props3d-live.js`: та же сцена, что и у героя (орткамера, свет-дети
   камеры, `polygonOffset`), но меши берутся из `dev/character-style-lab/assets/`
   без переезда в кадры.
2. Право входа: пропы ближе `PROP_LIVE_RADIUS` к герою (ближе всех их видно
   крупно), остальные остаются спрайтами. Порог — один параметр, не список.
3. Откат: как у героя — если живой кадр пустой/битый/потерян контекст, вид
   рисуется спрайтом, в штамп идёт причина.
4. Мера готовности: `tools/prop-live-raster.js` повторяет трюк
   `hero-live-raster.js` — силуэт живого рендера против растера листа, покрытие
   0.78–1.3, габарит Δ ≤ 6 px. Пока эта проверка не зелёная, спрайты не
   выключаются.

### Стадия 5 — пиксельный слой

* обводка кадра (`ink`, 2 px) уже есть у героя; у пропов её делает пекарь —
  при живом рендере обводка обязана приходить из того же `RIG_META.ink`;
* квантование тона: живой кадр прохода пост-слоя (2D-оверлей поверх canvas)
  приводит 32-битный градиент к тем же ступеням, что у листа — иначе герой
  «глянец» рядом с миром;
* сетка пикселя: пост-слой рисуется в `cell.w × cell.h` и тянется nearest —
  «гладкого пластика» в кадре не остаётся.

## Что остаётся 2D-кодом сознательно

HUD и весь текст, иконки и хотбар, полоски/штампы, вода и её блики (живой
2D-шиммер, `drawTerrainWater`), следы/тропинки, дым и искры (частицы), тени
(эллипсы опоры), вся «код-графика» предметов в руках. Причина простая: в
разрешении игры текст и интерфейсные формы в 3D только теряют, а кодовая
отрисовка остаётся единственным способом проверить картинку числом.

## Как пак попадает в репозиторий (и почему не целиком)

Три факта, которые определяют маршрут:

1. **Из песочницы сети нет.** Разрешены только `github.com`,
   `codeload.github.com`, `api.github.com`, npm и PyPI. `curl
   https://drive.google.com` и `https://www.dropbox.com` дают `000`.
2. **Коннектор умеет читать, но не складывать.** Из Google Drive/Dropbox
   файл приходит либо текстом, либо base64 в ответе инструмента: 6 МБ
   архива — это ~8 МБ текста. Для одного мелкого файла это терпимо, для
   пачки — нет. Рабочая область коннектором не пополняется.
3. **Git не возьмёт огромные файлы ни у меня, ни у вас.** GitHub блокирует
   отдельный файл > 100 МБ, а артефакт блока Arena ограничен ~128 МБ. В
   `Dropbox:/Pack` и в Google Drive (`New Beginning/Pack`, 23 архива) четыре
   архива больше этого порога: Modular Character Outfits 294 МБ, Downtown
   City 235 МБ, Medieval Village 161 МБ, Universal Base Characters 129 МБ.

Поэтому в репозиторий едет **не пак, а то, что из него поехало в игру**:
`.gltf + .bin + урезанная baseColor-текстура`. Именно для этого есть
`tools/pack-import.js`.

### Маршрут A — GitHub-зеркало (работает прямо сейчас, без вас)

CC0-паки Quaternius и KayKit лежат у авторов в репозиториях, и их можно
выбрать по одному каталогу — sparse-клон скачивает только его:

```
git clone -q --depth 1 --filter=blob:none --sparse \
    https://github.com/KayKit-Game-Assets/KayKit-Medieval-Hexagon-Pack-1.1 /tmp/kay
cd /tmp/kay && git sparse-checkout set addons/<пак>/Assets/gltf   # 39 МБ вместо 163
node tools/pack-import.js --src /tmp/kay/... --size 512 \
    --out dev/character-style-lab/assets/kaykit --models tent,barrel,... \
    --note "KayKit «Medieval Hexagon Pack 1.0» (CC0), зеркало github.com/…"
npm run props3d && npm run props:audit
```

Целый набор весит в Git сотни килобайт: KayKit-подборка — 256 КБ вместо
6.4 МБ архива, деревянная деревня — 288 КБ вместо 161 МБ.

Известные зеркала, которые уже пригодны: `KayKit-Game-Assets/*` (10 паков,
включая Character Pack «Adventures» с 5 ригнутыми мешами и 27 glTF-предметами),
`J-Ponzo/gltf-medieval-village-megakit` (откуда лежит `village`),
`J-Ponzo/gltf-universal-animation-library`, `walterpalladino/godot-quaternius-ultimate-stylized-nature`
(только `.fbx` + 237 МБ текстур — конвейеру не годится).

### Маршрут B — то, чего на GitHub нет (ваши Drive-архивы)

В `Google Drive → New Beginning/Pack` 23 архива. Нужны с толком, но зеркал для
них я не нашёл, поэтому варианты, по одному на пак:

* **распаковать и приложить к сообщению** loose `.glb`/`.gltf` (вложения
  попадают в рабочую область) — годится для 10–20 файлов;
* **залить loose-файлы в отдельный репозиторий на GitHub** (например
  `new-beginning-assets`, по 20–40 МБ на пак) — я склонирую его так же, как
  маршрут A, и сам сожму в `dev/…/assets/<пак>/`;
* **запустить `tools/pack-import.js` у себя** и закоммитить результат — команда
  ровно та, что в маршруте A, только `--src` указывает на распакованный архив.

Приоритет, если брать не всё: `Ultimate Nature Pack` (23 МБ, 178 типов —
лес и кусты), `Textured Stylized Trees` (12 МБ), `KayKit_ResourceBits` (8.5 МБ —
руда, хворост, бочки), `Farm Animals Animated` (7 МБ — живность),
`Fish Pack Animated` (1 МБ — вода оживает), `Characters_psx_1.2` (61 МБ —
PSX-текстуры = тот самый пиксельный слой из стадии 5). Не по жанру:
Downtown City, Realistic Car, Ultimate Gun.

### Что уже проверено на этом маршруте

KayKit «Medieval Hexagon» пришёл, запёкся и … **не подошёл** (таблица и замеры —
`dev/character-style-lab/assets/kaykit/README.md`): набор рисовался под вид
сверху на hex-тайл, и на 40-пиксельной фигуре его «палатка» — навес на четырёх
ножках, а камень — светлая плита. Польза от попытки реальна: атласный пак
показал, что пекарня трактует координату V «по-юнити» и на любых других
атласах покрасит моделé цветами соседних плиток. Это починено (см. блок 80.3
в `docs/CHANGELOG.md`).

## Облако и внешние ассеты

В `Dropbox:/Pack` лежит 23 архива (Quaternius/KayKit/PSX, от 1 МБ до 294 МБ).
Кандидаты по назначению:

* герой и одежда — `Universal Base Characters`, `Modular Character Outfits - Fantasy`, `Characters_psx_1.2` (PSX-текстуры = пиксельный слой из п.5);
* анимации — `Universal Animation Library` и `…Library 2` (оттуда уже взяты 9 клипов героя);
* фауна — `Farm Animals Animated`, `Fish Pack Animated`, `Bestiary - Dungeon Monsters Kit`;
* природа и постройки — `Ultimate Nature Pack`, `Textured Stylized Trees`, `KayKit_Forest_Nature_Pack`, `KayKit_ResourceBits`, `Farm Buildings`, `Medieval Village MegaKit`, `Medieval Weapons Pack`;
* не по жанру (не берём): `Downtown City MegaKit`, `Realistic Car Pack`, `Ultimate Gun Pack`.

**Блокер:** из песочницы внешняя сеть закрыта (`curl https://www.dropbox.com/`
→ `000`), коннектор отдаёт ссылку и читает текст, но не кладёт бинарник в
рабочую область. Поэтому распакованные наборы должны попасть в репозиторий
руками — в `dev/character-style-lab/assets/packs/<имя-пака>/`. Дальше всё
автоматизировано: `tools/pack-import.js --src <папка> --size 64` приводит GLB к
нужному размеру текстур, `tools/gltf-rig.js` читает меши, `npm run props3d`
печёт кадры, `npm run props:audit` меряет. В Git едет только геометрия:
деревянный набор из «Medieval Village MegaKit» — 288 КБ вместо 161 МБ архива.
