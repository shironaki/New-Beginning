## Доказанные ошибки доставки до блока 64

1. **Ложное впечатление гарантированной доставки.** `GET /__dev/notes`
   проверял доступность HTTP, но надпись обещала «заметки идут прямо в
   репозиторий». GET не проверяет результат будущего POST или Git push.
2. **Отказ push считался успехом.** Сервер возвращал `200`, имя файла и
   `pushed:false`. Клиент принимал имя файла за успех и убирал запись из
   очереди. Короткое предупреждение «НЕ запушена» тут же заменялось
   «заметка сохранена»/«отправлено».
3. **У успешно отправляемой заметки не было предварительной локальной
   копии.** Запись в браузер выполнялась только после отказа сети. Закрытие
   страницы во время запроса не защищалось журналом отправки.
4. **Тихая обрезка очереди:** `slice(-40)` удалял старые сообщения. Ошибка
   квоты localStorage не возвращалась вызывающему коду как отказ сохранения.
5. **Гонки:** два параллельных flush и новые записи между чтением и записью
   очереди могли перезаписать друг друга. Повтор POST создавал новый номер.
6. **Live reload** мог закрыть редактор заметки во время набора.
7. Ответ API перечислял лишь последние 20 файлов. Статусы «прочитана»,
   «изменён код», «принято владельцем» вообще не были квитанциями доставки.

Эти дефекты воспроизведены тестами очереди/HTTP, но **не выданы за доказанную
историю конкретных потерянных заметок**. Ошибка агента: предыдущий ответ
опирался на перечень файлов, не проверил цепочку доставки и слишком широко
сформулировал «заметки проверены».

## Что изменено в доставке

- Сначала локальная запись, потом сеть. Очередь снимается только по
  `ok:true + pushed:true + file`, а копия с квитанцией остаётся в архиве.
- Экспорт включает **все сохранённые записи**, не только ожидающие отправки.
  Старый ключ/формат очереди читается; лимит в 40 текстов больше не применяется.
- При нехватке места сначала убираются изображения, текст/контекст остаются;
  если и это невозможно — явный отказ, редактор не закрывается. Это не
  гарантия сохранения при очистке данных браузера или полном отказе диска.
- Один flush за раз, повтор каждые 30 с, таймаут сети, повторный POST/import
  распознаётся по стабильной идентичности и не создаёт копии.
- Сервер подтверждает публикацию Markdown в текущей рабочей ветке; не
  делает автоматический rebase живого checkout и не пишет в main/master.
- Новые PNG лежат в `.artifacts/notes/`, **не коммитятся**. Их копии остаются
  в браузерном экспорте, пока позволяет квота; старые PNG не удалялись.
- Обновление исходников ждёт закрытия редактора заметки. Ручное обновление
  страницы/закрытие несохранённого черновика всё ещё отличается от отправки.
- Строка состояния теперь различает доступность сервера, ожидающие записи
  и архив. Автоматическая синхронизация между разными origin не обещается.

### Как восстановить отсутствующие тексты

На **том же адресе, в том же браузере**, где они писались: пульт → Заметки →
«Выгрузить все файлом» (в старой версии — «Выгрузить файлом»). Передать один
JSON или перетащить его на разблокированную игру с dev-сервером. Импорт
безопасен для уже полученных заметок: повторы не создают новые номера.

Если старая версия уже удалила запись после `pushed:false` и ни один сервер
её не сохранил, новый код не может задним числом вернуть этот текст. Нельзя
просить владельца поверить в «всё исправлено», не получив сами сообщения.

## Готовка: найденные ошибки, а не восстановленный текст неизвестной заметки

- Состояние `cooking` ошибочно возвращало готовое блюдо при досрочном снятии
  с вертела/углей. Теперь до `done` возвращается исходный продукт.
- UI запускал котелок автоматически после второго клика: обещанные три
  ингредиента и отвар из одного были недоступны. Теперь отдельный запуск,
  1–3 ингредиента, вода/без воды и отмена выбора.
- Один экземпляр можно было выбрать дважды; списание происходило даже при
  отказе рецепта/занятом котелке. Теперь проверяется суммарное количество,
  продукты списываются только при успешном запуске.
- Готовый котелок можно было перезаписать новым блюдом. Теперь сначала сбор.
- При полном рюкзаке снятая еда исчезала. Теперь остаётся на месте.
- Окно на паузе делало ожидание готовки непонятным. Есть явное действие
  «Оставить готовиться», закрывающее окно; общий принцип паузы не сломан.

Нативный браузер: клики по топливу/розжигу/вертелу → обычные Game.update →
сбор жареного мяса; один лист мяты → котелок → Game.update → сбор отвара.
Результат: по одному блюду, исходные продукты израсходованы, 966 шагов
симуляции. Котелок для проверки предоставлен через модель, его получение
обычным прохождением **не заявляется** (строительство — не этот этап).

## Почему мир всё ещё плоский

`installPlayableRelief` действует только в `ashfall`. `PlayableRelief`
задаёт широкую гладкую террасу (~44 единицы высоты, максимум поля 56) и
ограничивает производные до 0.48. `projectGround` сдвигает столбцы текстуры
по y−height, сохраняя однозначную поверхность. В обычном мире нет видимых
вертикальных граней уступов, перекрытия нижней земли верхней, пространственной
композиции горных масс и теней от них. Остальные зоны сохраняют плоскую
проекцию. Камера, следуя за высотой героя, дополнительно уменьшает заметность
общего подъёма. Проверка «герой набрал высоту» доказывает механику, **не объём**.

Следующее изменение здесь должно вводить читаемые верх/стенку/основание,
передний и задний планы, свет/перекрытия и проходы с корректными коллизиями.
Это отдельная переработка обычного игрового участка, а не увеличение числа
height или ещё одно кольцо затенения. В блоке 64 она **не реализована**.
